# 安卓端语音对话集成说明

前端 `src/services/voice.js` 对语音输入做了**三层能力探测与自动降级**，安卓端只需要实现最上面一层
（原生桥），剩下的浏览器识别与录音上传会自动兜底：

| 优先级 | 能力 | 触发条件 | 实现位置 |
| --- | --- | --- | --- |
| 1 | 安卓原生桥 | `window.RailwayVoice` 存在且 `isAvailable()` 为真 | App 注入，见本文 |
| 2 | 浏览器语音识别 | `window.SpeechRecognition` / `webkitSpeechRecognition` 存在 | 前端自带 |
| 3 | 录音上传识别 | `navigator.mediaDevices.getUserMedia` + Web Audio 可用 | 前端采集 → `POST /api/ai/asr` |

播报同理：优先 `POST /api/ai/tts`（后端 edge-tts 神经网络音色），失败回落 `window.RailwayVoice.speak()`，
再失败回落 `window.speechSynthesis`。

> 结论：**不实现原生桥也能用**（安卓 WebView 支持 `getUserMedia` 时走第 3 层）。原生桥的价值是
> 直接复用系统语音识别（可离线、无需页面授权弹窗）与系统 TTS，体验最好。

---

## 一、桥接契约（App 必须遵守）

在 `WebView` 上注入名为 `RailwayVoice` 的对象，暴露 4 个方法：

| 方法 | 必需 | 说明 |
| --- | --- | --- |
| `isAvailable(): Boolean` | 否 | 返回 `false` 时前端认为原生不可用并降级。方法不存在时视为可用 |
| `startVoiceInput(): void` | 是 | 开始一次识别。结束后**必须**回调前端，见下 |
| `stopVoiceInput(): void` | 是 | 取消识别。前端超时（30s）或用户点「取消」时调用 |
| `speak(text: String): void` | 否 | 系统 TTS 播报。不存在时回落到 `speechSynthesis` |

识别结果通过页面全局函数回传（两个参数，错误时第一个传 `null`）：

```kotlin
// 成功
webView.evaluateJavascript("window.__railwayVoiceResult('" + escaped + "')", null)
// 失败
webView.evaluateJavascript("window.__railwayVoiceResult(null, '用户拒绝了麦克风权限')", null)
```

**务必对文本做 JSON 转义**（示例代码用 `org.json.JSONObject.quote`）。识别结果里出现单引号或换行
而没转义时，注入的 JS 会直接语法错误，前端会一直等到 30s 超时。

前端侧的回调实现在 `src/services/voice.js`：

```js
window.__railwayVoiceResult = (text, error) => { /* error 非空则 reject，否则 resolve(text) */ }
```

## 二、WebView 配置要点

```kotlin
webView.settings.apply {
    javaScriptEnabled = true                 // 前端是 Vue SPA，必须开
    domStorageEnabled = true                 // 令牌存在 localStorage
    mediaPlaybackRequiresUserGesture = false // 否则语音播报被自动播放策略拦截
    mixedContentMode = WebSettings.MIXED_CONTENT_COMPATIBILITY_MODE
}
webView.addJavascriptInterface(voiceBridge, "RailwayVoice") // 必须在 loadUrl 之前
```

`onPermissionRequest` 必须放行 `RESOURCE_AUDIO_CAPTURE`，否则页面里的 `getUserMedia`（第 3 层降级）
会被静默拒绝，表现为「点击开始说话没有任何反应」：

```kotlin
override fun onPermissionRequest(request: PermissionRequest) {
    if (request.resources.contains(PermissionRequest.RESOURCE_AUDIO_CAPTURE)) {
        if (hasMicPermission()) request.grant(request.resources)
        else { requestMic.launch(Manifest.permission.RECORD_AUDIO); request.deny() }
    } else super.onPermissionRequest(request)
}
```

## 三、权限与清单

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<queries>
    <intent><action android:name="android.speech.RecognitionService" /></intent>
    <intent><action android:name="android.intent.action.TTS_SERVICE" /></intent>
</queries>
```

安卓 11（API 30）起，`<queries>` 不声明会查不到系统语音识别服务，`SpeechRecognizer.isRecognitionAvailable()`
会返回 `false`，前端随即降级——这是最常见的「明明有识别功能却用不了」的原因。

## 四、线程模型

`@JavascriptInterface` 方法运行在 WebView 的 **JavaBridge 线程**，而 `SpeechRecognizer`、`TextToSpeech`
都要求**主线程**调用。示例代码里所有桥方法都 `Handler(Looper.getMainLooper()).post { ... }`，
回调也用 `webView.post { evaluateJavascript(...) }` 回到 UI 线程，两处都不能省。

## 五、接入步骤

1. 拷贝 `docs/android-sample/VoiceBridge.kt` 到工程（改包名）。
2. 按 `docs/android-sample/AndroidManifest.xml` 补权限与 `<queries>`。
3. 参照 `docs/android-sample/MainActivity.kt` 配置 WebView、申请录音权限、注入桥。
4. 把 `loadUrl(...)` 改成实际地址（本地 `http://<内网IP>:4028/`，公网 `http://<域名或IP>:14028/`）。
5. 打开页面 → 右下角 🤖 智能体 → 麦克风按钮，界面应显示「安卓原生麦克风」。

## 六、自检清单

| 现象 | 排查方向 |
| --- | --- |
| 麦克风按钮提示「当前环境不支持语音输入」 | WebView 未注入桥，且 `getUserMedia` 也不可用；检查 `addJavascriptInterface` 与 `javaScriptEnabled` |
| 界面显示「浏览器语音识别」而非「安卓原生麦克风」 | `isAvailable()` 返回了 false，或用的是系统 WebView 而非 App 内 WebView |
| 点击后一直转圈，30 秒后报超时 | 原生侧没回调 `__railwayVoiceResult`，或文本未转义导致注入脚本语法错误 |
| 播报没声音 | `mediaPlaybackRequiresUserGesture` 未置 false；或后端 TTS 不可用且系统 TTS 未初始化 |
| 识别结果为空 | 系统识别服务需要联网或未安装语音包，可在设置里安装「Google 语音服务」等 |
